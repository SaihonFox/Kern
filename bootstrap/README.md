# Self-hosted Kern compiler (bootstrap)

Компилятор Kern, написанный на самом Kern. Реализованы **лексер, AST и парсер**
(B0/B1); дальше — binder/typecheck, байткод и собственная VM.

## Запуск

```sh
kernc run bootstrap                 # AST встроенного примера
kernc run bootstrap src/main.kern   # AST файла (путь от папки bootstrap)
kernc test bootstrap                # тесты лексера и парсера
kernc check bootstrap
```

`main` объявляет `#[needs(fs.read("."))]` и читает путь из первого аргумента; без
аргумента печатает AST встроенного примера.

## Устройство

- `src/tokens.kern` — тип `token(kind, text, line, column)`.
- `src/lexer.kern` — `lex(str) -> list<token>`:
  - идентификаторы, числа (включая `0x`/`0b`/`0h`, `_` и суффиксы `2i64`),
  - строки с префиксами `f`/`r`/`x`/`v` (и их комбинациями) и escape-последовательностями,
  - символьные литералы `'k'`, `'\n'`;
  - однострочные `//`-комментарии;
  - пробелы и переводы строк с отслеживанием `line`/`column`;
  - одно-, двух- и трёхсимвольные операторы (`**`, `**=`, `..=`, `!in`, `!is`, `?.`, `?:`).
- `src/ast.kern` — AST: `ast_node(kind, text, line, column, children)`,
  `ast_param`, `ast_decl`, `ast_program`, `parse_error`, `parse_result`; текстовый
  дамп `dump_program`.
- `src/syntax.kern` — состояние парсера, работа с токенами, типы (`list<T>`,
  `fun(i32) -> i32`, `&T`/`*T`, tuples), балансировка скобок, атрибуты.
- `src/parser.kern` — рекурсивный спуск и Pratt-разбор выражений.
- `src/parser_tests.kern` — `#[test]`-проверки парсера и AST.

## Что разбирает парсер

- Объявления: `use`, `fun` (включая `fun name -> T expr`, расширения
  `fun list<T>.first`, локальные функции), `type`/`unit`/`unit!`, `op`,
  расширения-свойства (`i32 i32.double`), константы.
- Операторы: локальные переменные (в том числе несколько через запятую),
  деструктуризация `(i32 a, str b) = value`, множественное присваивание,
  `ret`, `if`/`else` (с блоком или одной инструкцией), `loop` во всех формах
  (`loop cond {}`, `loop i32 i in xs {}`, `loop var x in xs`, `loop 0..3 expr`),
  `stop`/`next`, `match`.
- Выражения: литералы, `f"..."`-строки, `nil`/`none`, `true`/`false`, `$`/`$field`,
  кортежи, списки и словари, вызовы с позиционными и именованными аргументами,
  члены (`a.b`), safe-call (`a?.b`), индексы, унарные и бинарные операторы с
  приоритетами (включая `**`, `?:`, `in`/`!in`, `is`/`!is`), диапазоны
  `a..b`/`a..=b` с шагом `:step`, `if`, `match`, `loop` и лямбды `fun (...) -> T`.

## Ограничения B1

- Тела `type`/`unit` (кроме заголовка с полями) сохраняются как `raw`-узел.
- Паттерны `match` хранятся текстом: валидация связываний и покрытия — задача binder'а.
- Атрибуты сохраняются строкой, но не разбираются в структуру.
- Нет `@type`/`@fun`/`~fun` (старый синтаксис из `examples/06`) и `async`/`await`.
- Парсер рекурсивный: очень глубокие выражения ограничены пределом кадров VM.

## Проверка

AST для `examples/01_basics`…`examples/05_functions` разбирается без ошибок;
`kernc test bootstrap` — 12 тестов. Следующий срез — **B2**: binder/typecheck.
