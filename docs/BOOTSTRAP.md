# Бутстраппинг Kern — чего хватает и чего нет

Цель бутстраппинга: компилятор Kern (lexer → parser → AST → binder → codegen/интерпретатор)
написан на Kern и запускается существующим `kernc`. C# остаётся только VM/нативным слоем.
Ниже — аудит по состоянию на 2026-11-02; это не обещание сделать всё сразу, а карта работ.

## Что уже есть

- Лексер/парсер-примитивы: `str`, `char`, `list<T>`, `dict<K,V>`, срезы, регулярные
  выражения (`kern.regex`), `match`, `is`-паттерны, диапазоны, `switch`-подобные цепочки.
- Модули и `use`, включая условную компиляцию `#[if(os = ...)]` (2026-11-02).
- Обобщения с выводом аргументов (рантайм reified), перегрузки, расширения, операторы.
- Замыкания, локальные функции, рекурсия, прямая TCO, генераторы `seq<T>`.
- `result<T,E>`, `T?`, `nil`, `match`, проверка исчерпываемости (предупреждения).
- Файлы/окружение/процессы/CLI/лог/конфиг: `file.*` (текст), `env`, `process`, `cli`, `log`.
- Коллекции: `list/array/dict/set`, `frozen_*`, `deque`, `priority_queue`, `sorted_*`,
  `bitset`, `ring_buffer`, `lazy`, `span`.
- Статическое состояние через `#`-поля типа; неизменяемые top-level константы.
- Новые библиотеки: `kern.security`, `kern.text` (Levenshtein/Markdown/шаблоны/Unicode),
  `kern.parse` (базовый разбор), `kern.num` (статистика/матрицы/FFT/complex).

## Блокеры (по приоритету)

1. **Двоичный ввод-вывод.** Сделано 2026-11-02: `file.read_bytes(path) -> result<list<u8>, str>`
   и `file.write_bytes(path, list<u8>) -> result<bool, str>`; `text.to_utf8`/`text.from_utf8`
   закрывают преобразование строк. Остаётся **`char` из кода** (`char.from_i32`):
   обратное направление (`char.code`) уже есть, а построение символа по коду пока нет.
   *Оценка: S.*
2. **Эффективная сборка строк.** Конкатенация `str` в цикле квадратична. Компилятору нужен
   `string_builder` (или `list<str>` + `join`, что уже работает, но требует дисциплины).
   *Оценка: S/M.*
3. **`use dotnet.X[...]` (способ C) не реализован.** Если bootstrap-компилятору понадобится
   прямой доступ к .NET (например, `System.Reflection.Metadata`), придётся либо добавить
   способ C, либо оставаться на нативных модулях. *Решение архитектурное — см.
   `DECISIONS_NEEDED.md`.*
4. **Глубина рекурсии.** Предел кадров 10 000 (настраивается `KERN_MAX_CALL_DEPTH`), TCO
   только для прямой саморекурсии. Рекурсивный спуск на очень глубоких выражениях может
   упереться в предел; нужен либо итеративный парсер, либо mutual TCO. *Оценка: M.*
5. **Нет `in`/`ref`/`out`.** Это не блокер: см. `docs/IN_REF_OUT.md` — ссылочная семантика
   через `type`, выходные значения через кортеж/`result`/`Out<T>`.
6. **Скорость VM.** Бутстрап-компилятор будет медленнее C#; для приемлемого времени
   компиляции нужен профиль и, возможно, кэш типов/строк. Профилировщик уже есть
   (`kernc run --profile`). *Оценка: L, отдельный этап.*
7. **Нет модульных глобальных переменных.** Всё состояние — `#`-поля типа. Для компилятора
   это нормально (синглтон-контекст), но код должен быть организован соответственно.
8. **Диагностика с несколькими местами** уже есть на уровне `Diagnostic` (Notes), но API для
   пользовательских компиляторов (свой `Diagnostic`) пока не выделен; `kern.parse` даёт
   `parse_error` с позицией и подчёркиванием.
9. **`str` — UTF-16.** Лексер может работать в UTF-16 code units; для корректных колонок
   с не-BMP символами нужен явный пересчёт (сейчас `str.len` считает UTF-16 units).

## Минимальные срезы бутстраппинга

- **B0.** `bootstrap/lexer.kern`: читает файл, печатает токены `kind text line:col` в
  формате, совместимом с C#-лексером. Проверка: golden-файл на `examples/01_basics`.
- **B1.** `bootstrap/parser.kern`: AST как union-типы, рекурсивный спуск, диагностика через
  `parse_error`. Проверка: AST для 01–05 совпадает с эталоном (текстовый дамп).
- **B2.** `bootstrap/binder.kern`: таблица символов, типы, перегрузки; проверка на
  `examples/06_generics_operators`.
- **B3.** `bootstrap/interp.kern`: исполнение AST (без `.kbc`) — доказательство семантики.
- **B4.** `bootstrap/codegen.kern`: запись `.kbc` (после блокера 1/2) и запуск VM.

## Проверочные команды

```text
kernc run bootstrap/lexer.kern examples/01_basics/src/main.kern
kernc run --profile bootstrap/parser.kern examples/01_basics/src/main.kern
kernc check bootstrap            # весь bootstrap-проект
```

## Вывод

Для лексера/парсера/binder'а языка уже хватает почти всего; первые реальные блокеры —
построение `char` из кода (1), затем производительность/глубина рекурсии (3/4).
`in`/`ref`/`out` не нужны. Полный бутстрапп — отдельный этап после закрытия пункта 1 и
решения по `use dotnet` (3).
