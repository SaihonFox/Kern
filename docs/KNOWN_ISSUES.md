# KNOWN_ISSUES — lessons from the old attempt (`reference/`) and traps to avoid

The reference code (~35k lines C#) was written **without ever being compiled** (the author had no dotnet). The owner built it on Windows in places and pasted errors.
Treat reference as a source of *ideas and structure*, not as truth. Below: every defect known so far, plus design traps.

## A. Compile-time traps (C#)
1. `Kern.Runtime.Math` namespace shadows `System.Math` inside `Kern.Runtime.*` → write `System.Math.Max(...)`.
2. Missing `using Kern.Runtime.Core;` for `Kv` (helpers `Kv.Of/As/Last/Strs`) in several files; missing `using Kern.Compiler.Semantics.Bound;` in the transpiler lowerer.
   Lesson: build early and often; do not trust "looks right".
3. In `Kern.Compiler` these names collide: `Syntax.{TypeKind, MemberFlags, FuncType}` vs `Bytecode.{TypeKind, MemberFlags}` vs `Semantics.Types.FuncType` → use `using Alias = …`.
4. `MacroData.cs` had warning CS9124 (primary-ctor parameter captured and also stored) — avoid capturing primary-ctor params into fields twice.
5. IDE0290/IDE0330 are only suggestions (primary ctor, `System.Threading.Lock`); not errors.
6. `ModuleMap.cs` maps C# namespaces → Kern modules; the namespace `Kern.Runtime.Math` exists, so name new C# namespaces carefully.

## B. Semantic bugs observed when the owner ran the examples
1. **`len` missing on `list<T>` / `dict<K,V>` (KRN2003)**: `len` was an *extension property* implemented as a generic static C# method on `KList<T>`; member lookup failed to unify the receiver with generic parameters.
   Design fix: first-class native members for builtin generics, not "extension with unification". Use `KERN_TRACE_MEMBERS=1`-style tracing in your new lookup code.
2. `contains` ambiguity (KRN1402) between list/collection overloads: make overload ranking prefer the more specific receiver (`list<T>` over `collection<T>`).
3. Conversions to `collection<T>` failed for `set/list/str` arguments and `streamwriter`→`stream` (KRN1404/KRN2001): the collection hierarchy conversion must be in `Conversions` and in generic inference.
4. `regex` type was not found when a program used `x"…"`/`use kern.regex[regex]` (KRN1001) — module/type registration gap.
5. **Attributes on properties/fields were never written into bytecode**, so DI `#[inject]` and reflection saw nothing (runtime panic "call of method now via nil"). Emit attributes for all members.
6. `panic("…")` as the last statement of a function with a return type gave KRN2104 ("missing return") because `panic` was not `never`. Decision: `never` type (see spec).
7. Lambda result type: `fun(i32 x) -> x * k` parsed `x` as the result type. The language requires `-> Type` before the body: `fun(i32 x) -> i32 x * k`.
8. Example 31 (`kbc`) reported "module 'mathx.vec' not found" simply because `mathx` had not been built as a `.kbc` first — the build order must be explicit (builder task or clear error message).
9. Old examples used things the language does **not** have: `:=`, `const`, leading `.` chains (now **added** by decision), `panic` as non-diverging.
10. Console encoding: Russian printed as `?` until UTF-8 was forced before first write.
11. SQLite native loading from a library folder needed `ResolvingUnmanagedDll` handling and `SQLitePCL.Batteries_V2.Init()` (stage 2).
12. `.NET` exceptions inside natives must become Kern panics with the inner-exception chain in the message.

## C. Design traps
- **Thread safety**: `Interpreter.Fork()` shares Module/Info/types/statics. Lazy caches in shared structures need locks (enum value cache, type factory, reflection `AddType`). KTask/Scheduler belong to the owner thread only; results come back via `Scheduler.BeginExternal/EndExternal`. `await` only on the thread that owns the task.
- `static` mutable state in the compiler/catalog (e.g. `NativeType.CollectionRoot`) breaks parallel xunit tests: avoid statics or make the harness serial.
- Native generics: a bare `T` in a C# signature must not be treated as `T?`; only explicit `T?`/`[Nullable]` means nullable. Reified type args via `[KernTypeArgs] KType[]`.
- `list<T>` element type is `object` for `snapshot()/keys()/values()` of generic native classes — pass element types explicitly.
- Do not use `MethodInfo.Invoke` on hot paths (compile delegates/expression trees).
- Text-expansion macros shift line numbers; keep a line map so diagnostics point to the original source.
- `.kbc` linker matches stubs by key; generated constructors and `<static-init>` have no source spans — design stable keys for them from day one; type matching by simple name conflicts for same-named types (decide a qualified key).
- `kbc` cache hash must include `.kbc` dependencies.
- Peephole optimizer must not merge an instruction that is a jump target with its predecessor; recompute line tables.

## D. Things that were only designed (never run): treat with extra care
Threads/`conc_*`/`parallel.*`, `.kbc` stubs+linker, macros, compile-time reflection, `define_type`, typed HTTP proxy, mocks, builder hash-skip, formatter token verification, `-O2`.

## E. Open gaps in the current implementation (as of 2026-10-27)
- **Backend library limits (2026-11-02):** `Kern.Lib.Backend` uses `HttpListener` (Windows `localhost` without admin is verified; other hosts/OSes may need URL ACL/prefix rights). Sessions and rate limits live in process memory; SSE has no replay buffer; static files have no caching/range support. Controllers bind primitive parameters by `kern.param_names` to route/query values and everything else from the JSON body; async controller methods are awaited via `KTask.GetResult`, but response streaming/cancellation is minimal. `#[controller]`/`#[get]`/`#[auth]`/`#[roles]` are library attributes, so the compiler still warns `KRN2307`.
- **DB/DI library limits (2026-11-02):** `Kern.Lib.Db` is verified end-to-end only on SQLite; PostgreSQL/MySQL connectors compile but need live servers. The ORM stores non-primitive fields as `to_str` text and does not parse them back (no JSON round-trip), has no migrations/relations, and uses naive snake_case+`s` table names. `Kern.Lib.Di` requires explicit lambda result types (`fun -> T`, not `fun { ... }`) for factories, `#[inject(optional: true)]` parsing is minimal, and `#[singleton]`/`#[transient]`/`#[scoped]`/`#[inject]` are library attributes, so the compiler warns `KRN2307`.
- **`kernc test` limits (2026-11-01):** only top-level/argument-less functions are intended; a `#[test]` method has an implicit receiver slot and currently fails as a test (parameter-count panic is reported as a failed test). Async tests are not pumped (the returned `task` is ignored); `assert*`/`fail` panics are the supported failure mechanism.
- **`is` patterns (2026-11-01):** full `match` pattern syntax is supported, but constructor/structural patterns still require `unit` types (the same restriction as `match`); bindings under `!is` or left of `||` are rejected with `KRN2101`; bindings are scoped to the condition/then-branch of `if`.
- **`with` limits (2026-11-01):** `x:{ a = 1 }` replaces instance fields only; computed and auto-properties are not addressed by property name (use the backing field name or add a setter path later). `unit!` is rejected. Inside a `[...]` literal a colon starts a dictionary entry, so a with-expression used as a list element must first be stored in a local variable. Diagnostics point at the assignment (`KRN2101`/`KRN2106`).
- **M9 limits (2026-11-01):** macros are expanded only through `SourceCompiler.CompileFiles`/project builds; single-file `CompileCore`, `kernc fmt` and `kernc repl` do not run them. Macro files compile as a separate mini-project and may use only std, libraries and other macro files. `reflect.define_type` supports a unit/class, fields and field/type attributes only - no generics, parents or methods; `attribute_info.instantiate()` is not implemented. `kernc dll` builds stubs from the macro-expanded sources (generated members are visible to consumers), but macro diagnostics point to the application site (generated text has no separate line map).
- **`!` required fields are enforced (fixed 2026-11-01, Q18).** The root constructor must assign every required instance field on all paths; `$` parameters and initializers count, branches are joined, violation is `KRN2192`. Inherited required fields are checked by the parent's own constructor.
- **`unit!` field stores inside construction are allowed (fixed 2026-11-01, Q17).** A `unit!` field may be written in its ctor or `init` accessor; writes after construction stay `KRN2105`.
- **Uninitialized fields and statics read as `none`.** There is no zero-initialisation, so `#i32 counter` without an initializer is `KValue.None` and arithmetic on it panics (`несовпадение типов операндов`). Static initializers run in declaration order, so a type declared before its dependency reads `none` - order the declarations accordingly (spec §8).
- **`panic(...)` has no bytecode yet** (`KRN2201`), so tests use `KernPanic`-producing operations instead; lambdas and local functions are still unbound (`KRN2109`), which weakens the "no `init` write inside a lambda declared in a ctor" test (it currently passes on the generic lambda error).
- **Constant literal conversion is not applied on assignment (found 2026-10-27, B1).** `u8 b = 1` reports `KRN2102` although a literal in range should convert implicitly (§15); the workaround in tests is a suffix (`1u8`). Same family as the numeric-literal conversion gap, not a bitwise bug.
- **A one-line block cannot hold a generic local declaration (found 2026-10-27, B1).** `fun f() { list<list<i32>> x }` fails the local-declaration lookahead at the missing statement terminator, while the multiline form works; the closing `>>` is counted correctly now. Low severity (formatting-sensitive), but it is a lookahead edge, not a language rule.

- **`result`/`task` have no runtime representation yet** (found 2026-10-27, B2): there are no `Ok`/`Err` constructors, no VM value type for `result<T, E>` and no `KResult` marshalling, so a Kern program cannot create or inspect a `result` value at runtime. `KRN2305` is still meaningful for declared return types and the discard path (`_ = expr`) is type-agnostic, but end-to-end result tests must wait for the result/std slice.
- **Native generic member return types are substituted in the binder** (fixed 2026-11-01): `list<T>.first()`/`last()`/`get()`/`remove_at()` return `T`, `map` returns `list<U>` and `filter`/`reverse`/`slice` return the collection type, `dict<K,V>.get()` returns `V` and `keys()`/`values()` return `list<K>`/`list<V>`; the CLR bridge signature (`KValue` → `object`) only stays in the symbol used by codegen, and the VM is unchanged. `set`/`queue`/`stack`/`observable`/`collection` are now covered by the same table (their factories and `to_list`/`contains` results are substituted); `iter` still has no native member table.
- **Contextual `str <-> list<char>` conversions are not implemented** (spec §3): neither `list<char> c = "text"` nor `str s = <char>['h', 'i']` has binder support yet.
- **Expected-type-driven literal kinds reach only some positions** (found 2026-10-27, B3b1): the hint is threaded to local initializers, assignments and the function's final expression; `if`/`match` branches and block expressions do not forward it, so an array literal inside them stays a `list` and needs an explicit local.
- **`array<T>[...]` prefix syntax is not parsed** (spec §3 corrected 2026-10-27, B3b1): the approved form is `<T>[...]` with an expected `array<T>`; the old "Сохраняется синтаксис `array<i32>[1, 2, 3]`" wording was replaced.
- **Open ranges in slices are parser errors** (found 2026-10-27, B5b2): `xs[..3]` and `xs[1..]` are not parsed; the implemented slice forms require both bounds (`xs[1..3]`, `xs[1..=3]`, negative bounds included).
- **`str` offsets are UTF-16 code units** (found 2026-10-27, B5b2): `s[i]`, slices and `str.len` count UTF-16 units, so a non-BMP character occupies two positions.
- **`op TypeName.[]` extension form is not parsed** (found 2026-10-27, B5a): only the member form inside `unit`/`type` works; the extension spelling from spec 10 is unsupported.
- **Same-arity indexer overloads pick the first convertible candidate** (found 2026-10-27, B5a): an exact type match wins, otherwise the first candidate decides and `Convert` may report `KRN2102`; there is no ambiguity diagnostic.
- **`op hash`/`op compare` protocol gaps** (updated 2026-11-01, Q23): `==`/`!=` now use a declared `op ==`/`op !=` (B6b2); `dict` keys honour `op hash`/`op ==` through the VM comparer (an `op ==` without `op hash` uses a constant hash). Remaining: a wrong-arity `op hash`/`op compare` declaration is still ignored until the call site; `x.hash()`/`x.compare(y)` have no unqualified form; a custom `op ==` without `op hash` makes dict lookups linear.
- **Grouped attribute syntax is not parsed** (found 2026-10-27, B7; **closed 2026-11-01**): `#[A, B]` is now split into independent `AttributeNode`s by the parser.
- **Attribute arguments and targets are only partially validated** (updated 2026-11-01): literal arguments are converted to `KConst` (bool/integers/floats/strings/chars), identifier text (e.g. `derive(hash)`, `cfg(test)`) is stored as a string constant; arity and allowed-target checks for `deprecated`/`must_use`/`inline`/`cfg`/`test` are still absent (only `#[derive]` is validated). Attributes on members are now parsed and stored (see below), so `KRN2307` sees them.
- **Property and module-level attributes are not emitted into `.kbc`** (updated 2026-11-01): type/unit, function/method/constructor/operator/accessor, field (instance/static) and property attributes are written to `TypeDef`/`FunctionDef`/`FieldDef`/`PropertyDef` and round-trip through `KbcWriter`/`KbcReader`; the disassembler prints them for types, functions and properties. `PropertyDef.OwnerType` belongs to format v2, so the version is not bumped. Module/global declaration attributes have no `KbcModule` slot yet.
- **Module attributes have no source syntax** (2026-11-01): the language cannot annotate a module/`use` declaration, so nothing is collected and nothing is emitted into `KbcModule.Attributes`; a module-level attribute feature needs a parser/spec decision first.
- **Dict key hashability is checked only at literal binding** (found 2026-10-27, B6a): `dict<K, V>` declarations, native constructors and other non-literal paths do not re-check that `K` is hashable; only `[...]`/`<K: V>[...]` report `KRN2101`.
- **Derived `hash`/`compare`/`clone` are not materialized as members** (found 2026-10-30, B8a; extended 2026-10-31, B8c): `#[derive(hash)]`/`#[derive(compare)]`/`#[derive(clone)]` are applied by the protocol binder path (`BoundHashExpression`/`BoundCompareExpression` with `Structural: true` → `ValueHashFields`/`ValueCompareFields`; `BoundCloneExpression` → `CloneObject`), not by synthesizing methods. The derived members therefore never appear in `MemberTable`, in `.kbc` type definitions or in reflection, and the `derive` attribute itself is not emitted into `.kbc` (same emission gap as B7). A later slice may synthesize real methods/attributes if reflection or other languages need them.
- **Recursive local functions require an explicit signature** (updated 2026-10-31): a local function with `-> T` and typed parameters is pre-declared and can call itself or a sibling (mutual recursion) through a captured `KCell`; a local function whose return type must be inferred still uses the old non-recursive path (its name is not declared while binding the body).
- **Native Kern type names are registered** (updated 2026-11-01): `NativeSymbolBuilder` merges `NativeCatalog.Types` into `ModuleSymbol.Types` as `SymbolKind.Native`, so self/return types and annotations like `regex`/`streamwriter` resolve; generic native types are rejected with a diagnostic. A native type **without constructors** no longer shadows a same-named module function, so a factory may share the type name (`regex("…")`; `BindCall` falls back to overload resolution). `NativeCatalog.MapReturn` now reads nullable-reference metadata, so a native `string?`/`T?` return becomes `str?`/`T?` (`kern.io` `read_line`, `regex.find`, `try_new`). The `kern.io` bridge still registers members on `object` and factories return `object` until the stream types are switched over.
- **`kern.regex` gaps** (found 2026-11-01, updated): `x"…"`/`fx"…"` literals now lower to `regex(pattern)`; `r.match(text) -> regex_match?` and the `regex_match` type are implemented (Q32); remaining: `regex.try_new(…)` / `regex.escape(…)` qualified static members through a type name (module functions are global, so `try_new(…)` works unqualified); `replace` with a function argument.
- **`fail` from `kern.test` is `void`, not `never`** (found 2026-10-31): `TypeMapping` has no CLR→`never` mapping, so code after `fail(…)` is not treated as unreachable.
- **Tuple gaps** (updated 2026-10-31): literals, named tuples from the expected type, `p.x`, destructuring, structural `==`/hash/compare and tuple dict keys work; tuple patterns in `match`, nested tuple destructuring and tuple `..rest` are not implemented; `TupleGet` validates only `index >= 0` (out-of-range panics in the VM). Named tuple literals `(x = 1, y = 2)` do not exist (DECISIONS_NEEDED Q27).
- **Module limitations** (2026-10-31, M3-F): only modules from the same project are linked; `.kbc`/library imports wait for M10. Multiple module-level static initializers are rejected (`KRN1014`); native modules are not item-validated (names are global); the plain `use path.module` form was removed, so old examples must use `[...]` or `.*`.
- **Iteration loop covers ranges, `list`/`array`, `dict` (key–value pairs) and `str` (chars)** (updated 2026-10-31): the loop-as-expression form collects body values into `list<T>`; `next` performs the counter increment first; a bare variable name writes to an existing local, `(a, b)` destructures an element tuple, and a missing binding ignores the element. Remaining gap: `async loop` (M5).
- **`main` may return `void` or `i32`** (updated 2026-11-01): `fun main() -> i32` is accepted and `kernc run` uses the value as the process exit code; `fun main(list<str> args)` receives the command-line arguments (spec §13). Async `main` is pumped by the CLI and works end-to-end (`await delay(ms)` included).
- **`ok`/`error` markers are reserved built-ins** (found 2026-11-01, hybrid `result` labels): `ResultTypes.OkMarker`/`ErrMarker` are injected into every module's type dictionary, and `TypeResolver` resolves the names `ok`/`error` before module symbols, so a user declaration named `ok`/`error` is shadowed. `type SomeOK[ok] { i32 code }` compiles, but `SomeOK(7)` needs a primary constructor (`type SomeOK(i32 code)[ok]`); a field-initializer form (`type SomeOK[ok] { i32 code = 7 }`) works with `SomeOK()`.
- **M7 std limits** (2026-11-01): `kern.reflection`'s `define_type` builder is minimal — no generic parameters, parents, methods or property metadata (fields only), and `type.fields` lists a type's own fields without inherited ones. Threads share one `Interpreter` state per worker (`Fork`) but ordinary `list`/`dict` are **not** thread-safe (use `conc_*`/`mutex`); `conc_*.snapshot()/keys()/values()` return `list<object>`; a blocking `worker.join()` inside async stops the event loop. Proxies (`mock`, `http_client.proxy`) cover abstract `@fun`s only, and `mock` matches arguments by value equality (no matchers). The job `pool`/`parallel` create a fork per worker thread, so a closure that captures mutable locals shares the cell across threads (program-level races are the program's responsibility, DECISIONS §D).
- **Generic member bodies are not specialized at runtime** (updated 2026-11-01): `Stack<T>` now runs end-to-end (`logs/generic_implicit.kern`) because `list + list` is implemented in the VM (`KValueMath.Arithmetic` returns a new `KList`) and generic bodies work on dynamic `KValue`s. What remains is **static signature erasure**: `TypeSigMap.From(TypeParameterType)` maps `T` to `object`, so `typeof<T>()` inside a generic function degrades to `object`; native collection members (`list<T>.first() -> T`) are now substituted in the binder and no longer depend on this. Reified specialization for `typeof` is a separate slice.
- **Async runs cooperatively, one owner loop per VM** (updated 2026-11-01): an `async fun` call starts a coroutine and returns a pending `task<T>`; the body runs until the first `await`, then the owner scheduler continues it. Completed tasks are sequential only in the sense that every continuation runs on the owning VM thread; `tasks.all/race/timeout`, `async loop` over `async_iter<T>`, `pipe<T>` and `thread.run` are implemented. A blocking `worker.join()` inside an async function still stops the event loop (use `await w.wait()`); cancellation is cooperative (`cancel_token.check()`/`token.delay`).
- **`panic`/`exit` are `never`** (fixed 2026-11-01): a block ending in `panic(...)` satisfies any return type, and `fun()->never` is assignable to `fun()->void`; the remaining erasure issue is static `TypeSig` for `typeof<T>()` in generic bodies (below).
- **`async_iter<T>` iteration is implemented** (2026-11-01): `async loop` calls `await next()` for `task<T?>` and stops on `nil`; `pipe_stream<T>` is the first native source. A non-async `loop` over an `async_iter` still reports `KRN2101`; only explicit `await` is allowed outside `async loop`.
- **`ctor(args)` constraint only checks existence** (found 2026-11-01): `ctor()` is enforced (a non-abstract type/unit with at least one non-static constructor; primitives/abstract/ctorless types are rejected with `KRN1401`), but the argument list inside `ctor(...)` is parsed and ignored — a call site is not matched against the constructor signature yet.
- **Project mode is module-per-file (updated 2026-11-01).** `ProjectCompiler` gives each file a module name (path without `src/`, `project a.b:` wins) and resolves `use`; `kernc run|build|check <dir>` uses it. `w.include(path)` builds child workspaces; a child target can be a source dependency (`t.deps = ["child:core"]`) and its tasks are addressed as `project:target:task`. Remaining limits: library/consumer types with the same simple name conflict in `kernc dll`; `t.lib` resolves `Kern.Lib.*.dll` only once such a stage-2 library exists.
