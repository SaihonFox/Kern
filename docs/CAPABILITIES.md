# Capabilities — зачем и как

Capabilities — это явные разрешения на опасные побочные эффекты. Они нужны, чтобы
запускать чужой или непроверенный Kern-код (плагины, примеры, сгенерированные
скрипты, пакеты) и заранее знать, что он может: открыть файл, сходить в сеть,
запустить процесс, обратиться к базе. Это не sandbox и не замена ОС-правам, а
декларация намерений + политика запуска + диагностика.

## Три уровня

1. **Декларация в коде.** Функция/модуль пишет, что ему нужно:

```kern
#[needs(net, fs.read("data/"), fs.write("out/"), process, db)]
fun fetch_and_save(url: str, path: str) { … }
```

Нативные модули объявляют свои требования сами через `[KernCapability]`
(`kern.io` — `fs.read`/`fs.write`, `kern.http`/`kern.net` — `net`,
`kern.process` — `process`, `kern.db` — `db`).

2. **Проверка компилятором.** Если у функции есть `#[needs]`, binder проходит по её
телу и требует, чтобы каждый вызов, которому нужна capability, был покрыт
объявлением. Непокрытый вызов — ошибка `KRN2401`. Так опечатка или забытый импорт
видны до запуска.

3. **Политика запуска.** `kernc run/debug` принимает:

```text
kernc run app --deny fs.write
kernc run app --deny all
```

По умолчанию разрешено всё. `--deny` запрещает перечисленные имена, `all` — все
capabilities сразу. Проверка выполняется в VM перед каждым нативным вызовом,
которому нужна capability; запрещённый вызов — `KernPanic` с русским сообщением.

## Что важно понимать

- Имена capabilities фиксированы: `net`, `fs.read`, `fs.write`, `process`, `db`.
  `fs.read("…")`/`fs.write("…")` — **scope**: синтаксис и хранение есть, но путь
  пока не ограничивается (проверяется только имя).
- Функция **без** `#[needs]` не проверяется компилятором; её вызовы ловит только
  runtime-политика. Это сделано для постепенной миграции: строгость включается
  там, где автор её объявил.
- Capabilities попадают в `.kbc` атрибутом `kern.capability`, поэтому политику
  можно применять и к готовому байткоду.
- Это не защита от вредоносного кода на уровне ОС: код всё равно выполняется в
  процессе VM и может делать всё, что разрешено хосту. Для жёсткой изоляции нужен
  отдельный процесс/контейнер и манифест пакета с подписью — отдельное решение.

## Ограничения (2026-11-03)

- path-scope не ограничивает путь;
- `kern.reflection`, `kern.env` и часть внешних библиотек ещё не аннотированы;
- манифест пакета с permissions/подписью не реализован.
